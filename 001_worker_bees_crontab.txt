# worker_bees schedule, written like a crontab
#
# One job per line:
#
#   minute  hour  day-of-month  month  day-of-week  script
#
#   minute        0-59
#   hour          0-23
#   day-of-month  1-31
#   month         1-12, or jan-dec
#   day-of-week   0-6 with Sunday as 0 (7 is Sunday too), or sun-sat
#
# Each time field can be:
#   *        every value
#   5        one value
#   1,15     a list
#   1-5      a range
#   */15     a step: every 15th value (8-18/2 works too)
#
# As in cron, when both day-of-month and day-of-week are set (neither is *),
# the job runs on days that match EITHER one: 0 6 1 * 1 runs on the 1st AND
# on every Monday.
#
# Lines starting with # are ignored, so put a # in front of a job to pause it.
#
# script: relative paths are looked up in scripts_directory (see
# 000_worker_bees_queue.toml), then in the worker_bees folder. A job's name
# in the queue is its script's file name, e.g. jobs/report.py -> report.
#
# ZZZ_build_queue.py turns these lines into .sched files in the queue folder,
# up to forward_days ahead. It only ever changes .sched files, so a job added
# to the queue by hand should use another ending, e.g. .request
#
# Workers start every few minutes, so a job may start a few minutes after
# its time. A job set to run every minute (* * * * *) runs in a burst each
# time a worker starts, and makes a lot of files: over 10,000 a week.
#
# After editing, check it with:   uv run ZZZ_build_queue.py --preview
# then apply it straight away:    uv run ZZZ_build_queue.py

# Rebuilds the queue every night. Keep this one.
0 22 * * *          ZZZ_build_queue.py
